## 1. 개요

### 1.1 목적
인증된 사용자가 시작·종료 일시가 있는 할일을 카테고리별로 관리하고, 할일을 팀 단위로 공유해 함께 보며, 월·주·일 캘린더에서 한꺼번에 조회할 수 있게 한다. 할일마다 누가 언제 무엇을 바꿨는지 이력을 남긴다.

### 1.2 문제 정의
| # | 문제 |
|---|------|
| P1 | 인증된 사용자가 개인별로 할일을 관리할 수 있는 앱이 없다. |
| P2 | 할일에 시작일과 종료일(기간)을 지정해 관리할 수 없다. |
| P3 | 할일을 월별·주별·일별 캘린더에서 한꺼번에 조회할 수 없다. |
| P4 | 팀원끼리 서로의 일정을 공유해 볼 수 없고, 팀 관리자가 팀원의 일정을 관리할 수 없다. |
| P5 | 할일을 누가 언제 바꿨는지 알 수 없다. |

## 2. 유비쿼터스 언어 (용어집)

| 용어 | 영문 | 정의 |
|------|------|------|
| 사용자 | User | 회원가입 후 로그인해 앱을 사용하는 사람. 자기 카테고리와 할일의 소유자다. |
| 팀 | Team | 일정을 서로 공유하는 사용자 그룹. 사용자는 여러 팀에 속할 수 있다. |
| 팀 구성원 | Team Member | 팀에 속한 사용자. 역할은 소유자 / 관리자 / 일반 팀원 중 하나다. |
| 팀 소유자 | Owner | 팀을 만든 사용자. 팀당 정확히 1명이다. 관리자 권한을 가지며, 구성원과 역할을 관리한다. |
| 팀 관리자 | Manager | 그 팀에 공유된 다른 구성원의 할일을 등록·수정·삭제·완료 처리할 수 있는 구성원(R19). |
| 일반 팀원 | Member | 그 팀에 공유된 할일을 조회만 할 수 있고, 변경은 자기 할일만 하는 구성원. |
| 공유 팀 | Shared Team | 할일이 공유된 팀. 그 팀 구성원이 할일을 볼 수 있다(R21). |
| 인증 | Authentication | 로그인으로 사용자 신원을 확인하는 것. 인증 전에는 회원가입·로그인 외의 기능을 쓸 수 없다. |
| 소셜 계정 연결 | User Identity | 사용자와 외부 제공자(Google) 계정을 잇는 기록. 제공자 이름과 그 제공자의 사용자 ID로 식별한다. |
| 소셜 전용 계정 | Social-only Account | 소셜 로그인으로만 가입해 비밀번호가 없는 계정. |
| 카테고리 | Category | 사용자가 자기 할일을 분류하려고 만드는 묶음. 본인에게만 보인다. |
| 기본 카테고리 | Default Category | 이름이 '기본'인 시스템 카테고리. 카테고리를 지정하지 않은 할일이 여기에 속한다. 저장되는 이름은 항상 '기본'이고, 화면에서는 현재 언어로 번역해 보여 준다(FR-13). |
| 할일 | Todo | 사용자가 기간 안에 수행할 작업 하나. |
| 변경 이력 | Todo History | 할일이 만들어지거나 바뀔 때마다 남는 기록. 누가, 언제, 무엇을 바꿨는지 담는다. |
| 시작 일시 | Start At | 할일을 시작하는 날짜와 시각(시:분). 시각을 입력하지 않으면 00:00이다. |
| 종료 일시 | End At | 할일을 마쳐야 하는 날짜와 시각(시:분). 시각을 입력하지 않으면 23:59이다. |
| 기간 | Period | 시작 일시부터 종료 일시까지. 양 끝을 포함한다. |
| 완료 여부 | Completed | 사용자가 할일을 완료로 표시했는지를 나타내는 값. 상태 중 유일하게 저장되는 값이다. |
| 할일 상태 | Todo Status | 시작 전 / 진행 중 / 완료 / 기한 초과. 계산으로 정해진다(5장). |
| 현재 일시 | Now | 상태를 판정할 때 쓰는 시점. '오늘'은 사용자 시간대 기준 현재 일시의 날짜다. |
| 필터 | Filter | 할일 목록을 팀·사용자·카테고리·상태로 좁혀 보는 조건. |
| 캘린더 뷰 | Calendar View | 할일을 월·주·일 단위 달력에 표시하는 조회 방식. |

## 3. 도메인 엔티티

### 3.1 관계
```
User N ──── M Team        (TeamMember로 연결, 역할 포함)
User 1 ──── N UserIdentity (소셜 계정 연결)
User 1 ──── N Category
User 1 ──── N Todo
Category 1 ──── N Todo    (Todo는 반드시 Category 하나에 속함)
Todo N ──── M Team        (TodoShare로 연결, 공유 팀)
Todo 1 ──── N TodoHistory
```

### 3.2 Team (팀)
| 속성 | 설명 | 비고 |
|------|------|------|
| id | 식별자 | |
| name | 팀 이름 | 필수, 1–50자. 시스템 전체에서 유일(앞뒤 공백 제거, 대소문자 무시) **[확정]** |
| createdAt | 생성일시 | |

### 3.3 TeamMember (팀 구성원)
| 속성 | 설명 | 비고 |
|------|------|------|
| teamId | 팀 | Team 참조 |
| userId | 사용자 | User 참조. (teamId, userId)는 유일 |
| role | 역할 | `OWNER`(소유자) / `MANAGER`(관리자) / `MEMBER`(일반 팀원). 팀당 `OWNER`는 정확히 1명. 구성원 추가 시 역할을 고르지 않으면 `MEMBER` (R18) **[확정]** |
| joinedAt | 가입일시 | |
| color | 캘린더 팀 색 | 선택. `RED`/`ORANGE`/`YELLOW`/`GREEN`/`TEAL`/`BLUE`/`VIOLET`/`PINK` 중 하나이고, 비어 있으면 화면이 자동 배정한다. 구성원마다 다른 개인 설정이라 본인 것만 본인이 바꾸며(역할 무관) 같은 팀 다른 구성원에게 영향을 주지 않는다. 사용자 결정(2026-11-05, 실행 계획 6.3 CL-01–CL-06) **[확정]** |

### 3.4 User (사용자)
| 속성 | 설명 | 비고 |
|------|------|------|
| id | 식별자 | |
| email | 로그인 ID | 이메일 형식, 최대 254자. 시스템 전체에서 유일(R16). 가입 후 변경 불가 **[확정]** |
| password | 비밀번호 | 8자 이상, UTF-8 72바이트 이하(상한은 bcrypt가 72바이트까지만 쓰기 때문. 영문은 72자, 한글 등은 더 적다). 해시로 저장. 소셜 전용 계정은 비밀번호가 없다(값 없음, R22) **[확정]** |
| name | 표시 이름 | 필수, 1–50자. 수정 가능 (R17) **[확정]** |
| timezone | 시간대 | 기본값 `Asia/Seoul`(KST). 일시 표시와 '오늘' 판정에 사용(R5). 수정 가능 **[확정]** |
| createdAt | 가입일시 | |

### 3.5 Category (카테고리)
| 속성 | 설명 | 비고 |
|------|------|------|

### 3.6 Todo (할일)
| 속성 | 설명 | 비고 |
|------|------|------|
| id | 식별자 | |
| ownerId | 소유 사용자 | User 참조. 이 할일이 누구의 일정인지 나타낸다 |
| categoryId | 소속 카테고리 | 필수. 소유 사용자의 카테고리여야 함. 소유자에게만 보인다 (R2, R7) |
| title | 제목 | 필수, 1–200자 **[확정]** |
| description | 상세 내용 | 선택, 최대 2,000자 **[확정]** |
| startAt | 시작 일시 | 날짜+시각(시:분), 필수. 시각 미입력 시 00:00 (R4, R5) |
| endAt | 종료 일시 | 날짜+시각(시:분), 필수. 시각 미입력 시 23:59 (R4, R5) |
| completed | 완료 여부 | 기본값 false |

- `status`(상태)는 저장하지 않는 계산값이다(5장).

| teamId | 공유 팀 | Team 참조. 할일 소유자가 속한 팀이어야 함. (todoId, teamId)는 유일 (R21) |
| sharedAt | 공유 일시 | |

### 3.8 TodoHistory (변경 이력)
| 속성 | 설명 | 비고 |
|------|------|------|
| id | 식별자 | |
| todoId | 대상 할일 | Todo 참조 |
| actorId | 변경한 사용자 | User 참조 |
| action | 변경 종류 | `CREATED` / `UPDATED` / `COMPLETED` / `UNCOMPLETED`. 요청 1건에 이력 1건. 완료 여부가 바뀐 요청은 `COMPLETED`(완료로) 또는 `UNCOMPLETED`(완료 해제로), 그 밖의 요청은 `UPDATED`다 **[확정]** |
| changes | 변경 내용 | 바뀐 필드별 이전 값 → 새 값(공유 팀 변경 포함). 같은 요청에서 완료 여부와 함께 바뀐 필드도 모두 포함한다. 카테고리 변경은 그 시점의 카테고리 이름도 함께 담아, 카테고리가 나중에 이름이 바뀌거나 삭제돼도 기록 당시 이름을 보여준다. `CREATED`는 처음 값 |
| changedAt | 변경 일시 | |

### 3.9 참조 무결성·데이터 제약 **[확정]**
| 대상 | 규칙 |
|------|------|
| 사용자·팀을 참조하는 FK (`TodoHistory.actorId`, `TodoShare.teamId`, `TeamMember.userId`, `TeamMember.teamId`, `Todo.ownerId`, `Category.ownerId` 등) | `ON DELETE RESTRICT`. 회원 탈퇴와 팀 삭제는 범위 밖이므로(7장) 참조되는 사용자·팀이 삭제되는 경우는 없다 |
| 할일 삭제 시 `TodoShare`, `TodoHistory` | FK `ON DELETE CASCADE`로 함께 삭제된다(R12, R20) |
| 구성원 제거 시 그 사람 할일의 그 팀 `TodoShare` | FK로 연쇄되지 않는다. 구성원 제거를 처리하는 service가 같은 트랜잭션에서 직접 `DELETE`한다(R21) |
| 팀당 `OWNER` 1명(R18) | 부분 유니크 인덱스 `UNIQUE (team_id) WHERE role = 'OWNER'`로 DB가 보장한다 |
| 소유권 이전(R18) | 위 인덱스 때문에 반드시 기존 소유자를 강등하거나 삭제한 뒤 새 소유자를 승격하는 순서로 처리한다. 반대 순서는 한 팀에 `OWNER`가 잠시 2명이 되어 인덱스 위반이다 |
| `Todo.categoryId`(R7, R9) | `(categoryId, ownerId)`가 그 사용자의 카테고리를 가리키는 복합 FK이고 `ON DELETE RESTRICT`다. 다른 사람의 카테고리를 가리킬 수 없고, 카테고리 삭제는 할일을 기본 카테고리로 옮긴 뒤에만 성공한다 |
| 사용자당 기본 카테고리 1개(R6, R8) | 부분 유니크 인덱스 `UNIQUE (owner_id) WHERE is_default`로 최대 1개를 DB가 보장한다. 최소 1개는 가입 트랜잭션(R6)과 삭제 금지(R8)가 보장한다 |
| 공유 팀은 소유자가 속한 팀(R21) | 구성원 변화에 따라 달라지므로 DB 제약으로 두지 않고 service가 검증한다 |
| 값 일관성 | `completed`가 true일 때만 `completedAt`이 있다(CHECK). 이메일은 소문자로만 저장한다(CHECK). 사용자 이름·팀 이름·카테고리 이름·할일 제목은 앞뒤 공백을 제거해 저장하고 공백만 있는 값은 DB도 거부한다(CHECK) |
| `UserIdentity.userId` | 위 `ON DELETE RESTRICT` 규칙의 예외로 `ON DELETE CASCADE`다. 소셜 계정 연결은 사용자에 딸린 기록이고, 회원 탈퇴가 범위 밖이라 실제로 삭제되는 경우는 없다 |

## 5. 할일 상태 정의

### 5.1 저장 여부
- 상태는 **저장하지 않고 조회할 때마다 계산한다.** 저장하는 값은 `completed`, `startAt`, `endAt`뿐이다.
- 이유: 시간이 지나면 상태도 저절로 바뀐다(예: 진행 중 → 기한 초과). 상태를 저장하면 배치 갱신이 필요하고 값이 어긋날 위험이 있다.

### 5.2 판정 규칙
입력: `completed`, `startAt`, `endAt`, `now`(분 단위). 위에서부터 차례로 평가하고, 처음 맞는 조건 하나로 정한다.

| ID (평가 순서) | 상태 | 조건 |
|------|------|------|
| S1 | **완료** | `completed = true` (일시와 무관) |
| S2 | **기한 초과** | `completed = false` 그리고 `now > endAt` |
| S3 | **시작 전** | `completed = false` 그리고 `now < startAt` |
| S4 | **진행 중** | `completed = false` 그리고 `startAt ≤ now ≤ endAt` |

### 5.3 일시 경계
- **시작 일시 정각**부터 진행 중이다(시작 포함).
- **종료 일시**까지 진행 중이다(종료 포함). 기한 초과는 **종료 일시가 지난 뒤부터**다.
- 시각 없이 종료일만 정한 할일은 종료가 23:59이므로 **그날 끝까지 진행 중**이고, **다음 날 00:00부터 기한 초과**다(예: 종료일 11/05 → 11/06 00:00부터 기한 초과).
- 시각 없이 시작일과 종료일을 같은 날로 정하면 그날 하루 동안 진행 중이다.

### 5.4 상태 간 겹침 처리
- 네 상태는 **서로 배타적**이다. 할일 하나는 항상 정확히 한 상태에 속한다.
- '기한 초과'는 '진행 중'의 하위 상태가 아니라 **별도 상태**다. 종료 일시가 지난 미완료 할일은 진행 중 필터에 나오지 않고 기한 초과 필터에만 나온다.
- '완료'가 가장 우선한다. 종료 일시가 지난 뒤에 완료한 할일도 '완료'다.
- R3(종료 일시 ≥ 시작 일시) 때문에 S2와 S3 조건은 동시에 성립할 수 없다.

### 5.5 필터

| F1 | 상태 필터 | 시작 전 / 진행 중 / 완료 / 기한 초과 중 하나. S1–S4 판정 결과 기준 |
| F2 | 카테고리 필터 | 본인 카테고리 중에서 고른다. 카테고리는 본인에게만 보이므로 이 필터를 쓰면 본인 할일만 나온다 (R2) |

| F4 | 팀·사용자 필터 | 팀 하나를 고르면 그 팀에 공유된 할일을, 사용자를 고르면 그 사용자의 할일 중 내가 볼 수 있는 것을 보여준다. 고를 수 있는 사용자는 내가 속한 팀들의 구성원이다. 기본값은 **팀 전체**로, 내가 볼 수 있는 모든 할일(내 할일과 내가 속한 모든 팀에 공유된 할일)이다. 목록과 캘린더에 모두 적용한다. **[확정]** |

## 7. 범위 밖 (Out of Scope)

- 팀 삭제, 소유자가 아닌 구성원 스스로 팀 나가기, 나가기와 무관한 소유자 위임, 초대 수락 절차 **[확정]**
- 삭제한 할일의 이력 조회, 이력으로 되돌리기 **[확정]**
- 알림·리마인더 (이메일, 푸시)
- 반복 할일
- 종일/시간 구분 (시각을 입력하지 않으면 시작 00:00, 종료 23:59로 처리)
- 우선순위, 태그, 하위 할일, 첨부파일
- Google 외 소셜 로그인(Naver, Kakao 등), 소셜 계정 연결 해제, 소셜 전용 계정의 비밀번호 설정
- 비밀번호 찾기·재설정, 이메일 인증
- 언어·테마의 서버 저장·기기 간 동기화, 사용자가 입력한 데이터(할일 제목 등)의 번역(서버가 만드는 기본 카테고리 이름 '기본'은 사용자 입력이 아니므로 화면에서 번역해 보인다), 오른쪽에서 왼쪽으로 쓰는 언어(RTL)
- 회원 탈퇴
- 삭제한 할일 복구(휴지통)
- 외부 캘린더 연동 (Google Calendar 등)
- 통계·리포트

> 범위 밖 항목은 모두 요구사항에 없어서 제외한 것이고 **[확정]**이다.
