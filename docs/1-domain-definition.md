## 1. 개요

### 1.1 목적
인증된 사용자가 시작일과 종료일이 있는 할일을 카테고리별로 관리하고, 월·주·일 캘린더에서 한꺼번에 조회할 수 있게 한다.

### 1.2 문제 정의
| # | 문제 |
|---|------|
| P1 | 인증된 사용자가 개인별로 할일을 관리할 수 있는 앱이 없다. |
| P2 | 할일에 시작일과 종료일(기간)을 지정해 관리할 수 없다. |
| P3 | 할일을 월별·주별·일별 캘린더에서 한꺼번에 조회할 수 없다. |

### 1.3 요구사항 추적
| ID | 기능 요구사항 (원문) | 문제 | 규칙 | 유스케이스 |
|----|----------------------|------|------|-----------|

| FR-02 | 카테고리별로 할일을 등록하며, 미지정 시 '기본' 카테고리를 적용한다. | P1 | R6–R11 | UC-05, UC-06 |
| FR-03 | 로그인한 사용자는 자신의 정보를 수정할 수 있다. | P1 | R17 | UC-04 |
| FR-04 | 할일 등록 시 시작일자·종료일자를 캘린더로 선택·지정할 수 있다. | P2 | R3–R5 | UC-06 |
| FR-05 | 할일 목록을 카테고리 / 시작 전 / 진행 중 / 완료 / 기한 초과로 필터링할 수 있다. | P2 | S1–S4, F1–F3 | UC-07 |

## 2. 유비쿼터스 언어 (용어집)

| 용어 | 영문 | 정의 |
|------|------|------|
| 사용자 | User | 회원가입 후 로그인해 앱을 사용하는 사람. 모든 데이터의 소유자다. |
| 인증 | Authentication | 로그인으로 사용자 신원을 확인하는 것. 인증 전에는 회원가입·로그인 외의 기능을 쓸 수 없다. |
| 카테고리 | Category | 사용자가 할일을 분류하려고 만드는 묶음. |
| 기본 카테고리 | Default Category | 이름이 '기본'인 시스템 카테고리. 카테고리를 지정하지 않은 할일이 여기에 속한다. |
| 할일 | Todo | 사용자가 기간 안에 수행할 작업 하나. |
| 시작일 | Start Date | 할일을 시작하는 날짜(시각 없음). |
| 종료일 | End Date | 할일을 마쳐야 하는 날짜(시각 없음). |
| 기간 | Period | 시작일부터 종료일까지. 양 끝 날짜를 포함한다. |
| 완료 여부 | Completed | 사용자가 할일을 완료로 표시했는지를 나타내는 값. 상태 중 유일하게 저장되는 값이다. |
| 할일 상태 | Todo Status | 시작 전 / 진행 중 / 완료 / 기한 초과. 계산으로 정해진다(5장). |
| 기준일(오늘) | Today | 상태를 판정할 때 쓰는 날짜. 사용자 시간대 기준의 현재 날짜다. **[가정]** |
| 필터 | Filter | 할일 목록을 카테고리나 상태로 좁혀 보는 조건. |
| 캘린더 뷰 | Calendar View | 할일을 월·주·일 단위 달력에 표시하는 조회 방식. |

## 3. 도메인 엔티티

### 3.1 관계
```
User 1 ──── N Category
User 1 ──── N Todo
Category 1 ──── N Todo   (Todo는 반드시 Category 하나에 속함)
```

### 3.2 User (사용자)
| 속성 | 설명 | 비고 |
|------|------|------|
| id | 식별자 | |
| email | 로그인 ID | 시스템 전체에서 유일. 가입 후 변경 불가 **[가정]** |
| password | 비밀번호 | 해시로 저장 **[가정]** |
| name | 표시 이름 | 수정 가능 (R17) |
| timezone | 시간대 (예: Asia/Seoul) | 기준일(오늘) 판정에 사용(R5). 가입 시 기기 시간대로 설정, 수정 가능 **[가정]** |
| createdAt | 가입일시 | |

### 3.3 Category (카테고리)
| 속성 | 설명 | 비고 |
|------|------|------|
| id | 식별자 | |
| ownerId | 소유 사용자 | User 참조 |
| name | 카테고리 이름 | 같은 사용자 안에서 유일 |
| isDefault | 기본 카테고리 여부 | 사용자당 정확히 1개만 true |

### 3.4 Todo (할일)
| 속성 | 설명 | 비고 |
|------|------|------|
| id | 식별자 | |
| ownerId | 소유 사용자 | User 참조 |
| categoryId | 소속 카테고리 | 필수. 미지정 시 기본 카테고리 |
| title | 제목 | 필수 **[가정]** |
| description | 상세 내용 | 선택 **[가정]** |
| startDate | 시작일 | 날짜만 저장, 필수(4장 R4 참고) |
| endDate | 종료일 | 날짜만 저장, 필수(4장 R4 참고) |
| completed | 완료 여부 | 기본값 false |
| completedAt | 완료 처리 일시 | 완료 시 기록, 완료 해제 시 비움 **[가정]** |
| createdAt / updatedAt | 생성·수정 일시 | |

- `status`(상태)는 저장하지 않는 계산값이다(5장).

## 4. 비즈니스 규칙

| ID | 규칙 |
|----|------|
| R1 | **인증 필수**: 회원가입과 로그인을 뺀 모든 기능은 인증된 사용자만 쓸 수 있다. |
| R2 | **데이터 소유권**: 사용자는 자기 소유의 카테고리와 할일만 조회·등록·수정·삭제할 수 있다. 다른 사용자의 데이터는 있는지 여부도 드러내지 않는다(조회 결과 '없음'으로 처리). **[가정: 존재 은닉 방식]** |
| R3 | **기간 유효성**: 종료일 ≥ 시작일. 같은 날도 허용한다(하루짜리 할일). |
| R4 | **날짜 필수**: 시작일과 종료일은 항상 값을 가진다. 등록할 때 비어 있으면 다음과 같이 채운다. **[가정]** (근거: 상태 판정과 캘린더 표시가 두 날짜 모두에 의존한다.)<br>· 둘 다 없음: 시작일 = 종료일 = 오늘<br>· 시작일만 있음: 종료일 = 시작일<br>· 종료일만 있음: 시작일 = min(오늘, 종료일)<br>채운 결과는 항상 R3을 만족한다. |
| R5 | **날짜 단위**: 시작일과 종료일은 시각 없이 날짜만 다룬다. 기준일(오늘)은 `User.timezone` 기준의 현재 날짜다. **[가정]** |
| R6 | **기본 카테고리 생성**: 회원가입 시 이름이 '기본'인 카테고리를 자동으로 만든다. **[가정: 자동 생성 방식]** |
| R7 | **기본 카테고리 할당**: 할일을 등록할 때 카테고리를 지정하지 않으면 기본 카테고리에 속한다. 수정할 때 카테고리를 바꾸지 않으면 기존 카테고리를 그대로 유지한다. |
| R8 | **기본 카테고리 보호**: 기본 카테고리는 삭제하거나 이름을 바꿀 수 없다. **[가정]** |
| R9 | **카테고리 삭제 시 할일 처리**: 카테고리를 삭제하면 그 안의 할일은 삭제하지 않고 기본 카테고리로 옮긴다. **[가정]** |
| R10 | **카테고리 이름 유일성**: 같은 사용자 안에서 카테고리 이름은 중복될 수 없다. 앞뒤 공백을 제거한 뒤 비교한다. 대소문자 구분 여부는 구분하지 않는 것으로 한다. **[가정: 공백·대소문자 처리]** 다른 사용자와는 이름이 같아도 된다. |
| R11 | **카테고리 이름 필수**: 공백만으로 된 이름은 허용하지 않는다. **[가정]** |
| R12 | **할일 삭제**: 삭제는 영구 삭제이며 복구하지 않는다. **[가정]** |
| R13 | **할일 수정**: 편집 화면에서 제목·설명·카테고리·시작일·종료일·완료 여부를 수정할 수 있다. 수정할 때도 R3을 검증한다. |
| R14 | **완료 처리**: 완료 여부는 사용자가 직접 바꾼다. 완료는 해제할 수 있다. 날짜와 관계없이(시작 전이라도) 완료할 수 있다. **[가정]** |
| R15 | **캘린더 표시**: 할일은 시작일부터 종료일까지 기간 안의 모든 날짜에 표시된다. 월·주·일 뷰에서는 해당 범위와 기간이 하루라도 겹치는 할일을 모두 표시한다. |
| R16 | **이메일 유일성**: 회원가입 시 이메일은 시스템 전체에서 중복될 수 없다. **[가정]** |
| R17 | **프로필 수정**: 사용자가 수정할 수 있는 정보는 이름, 비밀번호, 시간대다. 비밀번호를 바꿀 때는 현재 비밀번호를 확인한다. 이메일은 바꿀 수 없다. **[가정]** |

## 5. 할일 상태 정의

### 5.1 저장 여부
- 상태는 **저장하지 않고 조회할 때마다 계산한다.** 저장하는 값은 `completed`, `startDate`, `endDate`뿐이다.
- 이유: 날짜가 바뀌면 상태도 저절로 바뀐다(예: 진행 중 → 기한 초과). 상태를 저장하면 배치 갱신이 필요하고 값이 어긋날 위험이 있다.

### 5.2 판정 규칙
입력: `completed`, `startDate`, `endDate`, `today`. 위에서부터 차례로 평가하고, 처음 맞는 조건 하나로 정한다.

| ID (평가 순서) | 상태 | 조건 |
|------|------|------|
| S1 | **완료** | `completed = true` (날짜와 무관) |
| S2 | **기한 초과** | `completed = false` 그리고 `today > endDate` |
| S3 | **시작 전** | `completed = false` 그리고 `today < startDate` |
| S4 | **진행 중** | `completed = false` 그리고 `startDate ≤ today ≤ endDate` |

### 5.3 날짜 경계
- **시작일 당일**은 진행 중이다(시작일 포함).
- **종료일 당일**은 진행 중이다(종료일 포함). 기한 초과는 **종료일 다음 날부터**다.
- 시작일 = 종료일인 할일은 그날 하루만 진행 중이다.

### 5.4 상태 간 겹침 처리
- 네 상태는 **서로 배타적**이다. 할일 하나는 항상 정확히 한 상태에 속한다.
- '기한 초과'는 '진행 중'의 하위 상태가 아니라 **별도 상태**다. 종료일이 지난 미완료 할일은 진행 중 필터에 나오지 않고 기한 초과 필터에만 나온다.
- '완료'가 가장 우선한다. 종료일이 지난 뒤에 완료한 할일도 '완료'다.
- R3(종료일 ≥ 시작일) 때문에 S2와 S3 조건은 동시에 성립할 수 없다.

### 5.5 필터
| ID | 필터 | 정의 |
|----|------|------|
| F1 | 상태 필터 | 시작 전 / 진행 중 / 완료 / 기한 초과 중 하나. S1–S4 판정 결과 기준 |
| F2 | 카테고리 필터 | 선택한 카테고리에 속한 할일 |
| F3 | 필터 조합 | F1과 F2는 함께 적용(AND)할 수 있다. 필터를 고르지 않으면 전체를 보여준다. **[가정]** |

## 7. 범위 밖 (Out of Scope)

- 할일 공유, 협업, 다른 사용자에게 할당
- 알림·리마인더 (이메일, 푸시)
- 반복 할일
- 시각(시:분) 단위 일정, 종일/시간 구분
- 우선순위, 태그, 하위 할일, 첨부파일
- 소셜 로그인, 비밀번호 찾기·재설정, 이메일 인증
- 회원 탈퇴
- 삭제한 할일 복구(휴지통)
- 외부 캘린더 연동 (Google Calendar 등)
- 통계·리포트

> 범위 밖 항목은 모두 요구사항에 없어서 제외한 것이다. **[가정]**
