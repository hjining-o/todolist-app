> 표기
> - 기준 문서의 ID를 그대로 쓴다: FR, R, S, F, UC, P(도메인 정의서), SC, M, A, K(PRD). 이 문서는 시나리오 ID **US-xx**(정상 흐름)와 **EX-xx**(예외·경계)만 더한다.
> - 수용 기준은 **'FR-xx #n'**으로 참조한다(PRD 4.3에서 해당 FR의 n번째 체크 항목).
> - 기준 문서에 없던 사항(**C-xx**)은 이해관계자 결정(2026-11-04)으로 정했고 6장에 모았다. 본문에서는 [C-xx]로 근거를 표시한다. 6.5의 항목은 기준 문서에 반영했다(C-01–C-17은 도메인 v0.11, PRD v0.7, C-19–C-22는 도메인 v0.12, PRD v0.11, C-24–C-28은 도메인 v0.15, PRD v0.17). C-18은 결번이다(v0.5에서 삭제). C-24–C-28은 2026-11-05 결정이다(6.1.1).
> - 예시 기준: 오늘 = 2026-11-04(수), 사용자 시간대 = `Asia/Seoul`(KST). 예시 데이터(1.3)는 설명용이다.
> - 변경 이력은 문서 맨 아래(7장)에 있다.

## 1. 개요

### 1.1 목적
도메인 정의서의 규칙(R1–R22, S1–S4, F1–F4)과 PRD의 수용 기준(4.3)·화면(SC-00–SC-09)을 사용자 행동 순서로 풀어 쓴다. 구현·테스트 담당자가 시나리오 단위로 P0/P1 수용 기준을 검증할 수 있게 한다(M6).

### 1.2 행위자
| 행위자 | 정의 | 근거 |
|--------|------|------|
| 비인증 사용자 | 로그인하지 않은 사람. 회원가입·로그인(Google 소셜 로그인 포함)만 할 수 있다 | R1, UC-01, UC-02, UC-15 |
| 사용자 | 로그인한 사람. 자기 카테고리·할일·프로필의 소유자 | R1, R2, R17 |
| 팀 소유자 | 팀을 만든 사용자(`OWNER`). 팀당 1명. 관리자 권한 + 구성원·역할 관리 | R18, UC-13, UC-14 |
| 관리자 | `MANAGER`(및 소유자). 그 팀에 공유된 다른 구성원의 할일을 등록·수정·삭제·완료 처리 | R19 |
| 일반 팀원 | `MEMBER`. 그 팀에 공유된 할일 조회만. 변경은 자기 할일만 | R2, 도메인 2장 |

- 권한 매트릭스(4장)에서는 할일 기준 관계로 **할일 소유자**(그 할일의 `ownerId`)와 **비구성원**(그 할일의 공유 팀 어디에도 속하지 않은 사용자)을 함께 쓴다.

| 3 | (자동) | 가입 성공 즉시 액세스 토큰(15분)과 리프레시 토큰(7일)을 httpOnly 쿠키로 발급하고 할일 목록으로 이동. 별도 로그인 없음 | SC-02 → SC-03 | PRD 5.2, [C-01] |

- 계정 1건, 카테고리 '기본' 1건, 할일 1건이 생긴다. 할일은 A 본인에게만 보인다.

- (FR-10 구현 후) '주간 보고서'에 `CREATED` 이력 1건이 생긴다(R20).

## 4. 권한 매트릭스

### 4.1 할일 단위 권한
할일 T: 소유자 = 사용자 U, 공유 팀 = 팀 X. 열의 역할은 팀 X에서의 역할(U가 아닌 사람)이다.

| 행위 | 할일 소유자(U) | 팀 소유자 | 관리자 | 일반 팀원 | 비구성원 | 근거 |
|------|:---:|:---:|:---:|:---:|:---:|------|
| 조회(목록·캘린더·상세) | O | O | O | O | 404 | R2, R21 |
| 카테고리 보기 | O | 비노출 | 비노출 | 비노출 | 404 | R2, PRD 5.2 |
| 카테고리 변경 | O | 403(필드 비활성) [C-15] | 403(필드 비활성) [C-15] | 403 | 404 | R7, R13, R19 |
| 수정(제목·설명·일시) | O | O | O | 403(읽기 전용 화면) [C-14] | 404 | R13, R19, A12 |
| 완료·해제 | O | O | O | 403 | 404 | R14, R19, A12 |
| 삭제 | O | O | O | 403 | 404 | R12, R19, A12 |
| 공유 팀 변경 | O (자기가 속한 팀만) | 403 | 403 | 403 | 404 | R21, FR-11 #4 |
| 공유 팀 목록 보기 | 전체 | 자기가 속한 팀만 | 자기가 속한 팀만 | 자기가 속한 팀만 | 404 | R21 |
| 이력 조회 | O (카테고리 변경 포함) | O (카테고리 변경 제외) | O (카테고리 변경 제외) | O (카테고리 변경 제외) | 404 | R20 |
| U를 대상으로 새 할일 등록 | (본인 등록) | O | O | 불가(소유자 필드 없음, API는 403 `FORBIDDEN`) [C-21] | 400 `INVALID_OWNER` | R19, [C-16] |

- 공유 팀이 없는 할일은 U 외 모든 사용자가 '비구성원' 열에 해당한다(R21).
- 한 사람이 할일의 공유 팀 중 한 곳에서라도 관리자(또는 소유자)이면 관리자 열을 따른다. 관리 권한은 '그 팀에 공유된' 할일에 생기기 때문이다(R19).
- 역할은 요청마다 DB로 확인하므로 관리자 해제·구성원 제거가 바로 반영된다(PRD 5.2, US-15).

### 6.2 오류 응답 (C-05)
- 응답 본문 형식: `{ "error": { "code": "<코드>", "message": "<한국어 메시지>" } }`. 입력 오류는 `fields`에 필드별 메시지를 더할 수 있다. 서버 메시지는 한국어 한 가지이고, 화면은 `code`의 번역을 우선 보여 준다(C-27).
- 현재 비밀번호 오류는 401이 아니라 400을 쓴다. 401은 프론트엔드가 토큰 갱신을 시도하고, 갱신도 실패하면 로그인 화면으로 보내는 신호이기 때문이다.

### 6.3 입력 길이 (C-03)
앞뒤 공백을 제거한 뒤 글자 수로 센다. 단, 비밀번호는 공백을 제거하지 않고 입력값 그대로 검사한다[C-23]. 클라이언트는 입력을 제한하고, 서버가 최종 검증한다(400 `VALIDATION_ERROR`).

| 항목 | 필수 | 길이 | 근거 |

| 할일 설명 | - | 최대 2,000자 | 일반적인 메모 상한. 본문 100KB 제한 안 |
| 카테고리 이름 | O | 1–50자 | 이름과 같은 기준 |
| 팀 이름 | O | 1–50자 | 이름과 같은 기준 |
